How this project maps to the role
AI curiosity
I built this because I wanted to understand the Model Context Protocol at a deeper level — not just consume it but expose it. protein-mcp is a real MCP server: tools are registered with proper schemas, the routing layer dispatches to the right handler, and the response format is designed for agent consumption. I stay close to what's happening in the AI tooling ecosystem.
Engineering craft
The project is TypeScript throughout. Tool schemas are strictly typed; the data layer is deliberately separated from the routing layer so it can be swapped out (e.g. swap FAO CSV parsing for a database query). I started with the interface before the implementation — a habit from TDD thinking.
Honest about WIP
The data hydration layer isn't complete — the FAO dataset has messy structure and I'm mid-parse. I'm sharing it anyway because the architecture decisions are the interesting part, and I believe in showing work in progress. Shipping iteratively and being transparent about state is how good teams build fast.
